# 航空箱材质工程图 · 脚本版 01

本轮依据 2026-09-17 最新要求，采用 Pillow 逐像素绘制、脚本构建 Blockbench 工程、同源网格渲染及排版。没有调用 AI 图像生成或图像 API。

## 查看

- `index.html`：八项工程图浏览入口，点击查看原图或下载模型。
- `00_all_assets.png`：八项总览（1800×2400）。总览缩略图经过排版缩小；检查像素请用独立工程图和原始 PNG。
- `sheets/`：8 张独立 1800×1200 PNG 工程图。
- `models/00_all_assets_showcase.bbmodel`：八项同场景，每项一个分组。
- `models/`：13 个单项/状态模型，另加 1 个总览，共 14 个。
- `textures/`：100 张 RGBA PNG，包括 84 张 16×16，及 16 张保留图集布局的 32×32 PNG。数量包含共用色块、连接玻璃样片和换色掩膜，并非 100 个独立成品资产。
- `renders/`：从 `.bbmodel` 中的网格、UV 和内嵌 PNG 直接渲染的透明背景预览。
- `validation.json`：纹理尺寸、颜色数、alpha 值、模型纹理引用和 UV 边界检查。
- `packager-mask-audit.json`：原打包机与流体打包机换色区域对照；确认掩膜外像素不变。

## 模型与贴图的关系

Blockbench 文件内嵌贴图，同时保留指向 `textures/` 的相对路径。所有源贴图在 16×16 画布逐像素绘制；原打包机保留其 32×32 图集布局。源稿与图中纹理放大区使用最近邻采样，不使用照片、抗锯齿滤镜或随机噪声。

模型为 Blockbench 通用网格格式（`free`），可修改分组、面和 UV。三种平面物品由原始 PNG 的不透明像素挤出 1 单位厚度，仅用于预览；背包 PNG 仍是 16×16。

工程图主图和正投影图由本地脚本读取保存后的 `.bbmodel` 渲染，不是另画的伪 3D 效果。Blockbench 与脚本的默认灯光、玻璃排序可能略有区别。本轮已在本机 Blockbench 打开回响激发器及八项模型总览，检查分组、贴图、透明玻璃和晶体结构。总览含 8 个资产分组及 458 个网格部件，物品逐像素挤出使部件数较多，接入游戏前会优化。

多部件模型并不强行塞进“一张面贴图”：激发器分别使用底座、幽匿环、水晶分面；航空箱分别使用顶底板、实体立柱、透明玻璃。工程图下栏是各方向材质设计及主要 UV 源稿，右上六面是实际模型投影；这些不是同一个概念。航空箱 `crate_window` 和连接样片提供后续面片实现的设计候选，当前模型采用实体外框与独立玻璃层。

## 制作范围

这是造型、配色与结构确认稿，不是安装即用的资源包。尚未写入项目运行资源，也未启动 Minecraft。

下一轮接入时需完成：将通用网格转换为游戏支持的模型/渲染形式、整理最终 UV 图集、为多方块连接纹理匹配 Create 的实际索引和上下文、透明层排序与剔面、正确的手持/掉落显示变换、打包机水平/垂直/联动与动画、激活发光渲染逻辑。当前激活态以像素颜色表示，未附着游戏 emissive 元数据。连接样片仅按 N/E/S/W 四边 bitmask 命名，未声称与 Create 的连接纹理格式直接兼容。

示意羊是工程预览分组，未画入玻璃 PNG；使用 `05_creature_parcel.bbmodel` 获取空包裹，`05_creature_parcel_display.bbmodel` 含示意羊。程序里的真实生物渲染留下一轮。

## 来源与重建

打包机换色参考：本地 `create-1.21.1-6.0.10.jar`，以及此前提取的 Fluid Logistics 材质（提取目录未记录版本）。`references/` 保存 11 张 Create 原图及 11 张 Fluid Logistics 对照图，便于重现精确换色掩膜。打包机虹膜与边框保留 Create 原像素布局，其他新设计由脚本绘制；本轮打包机主体为独立工程概念模型，没有宣称完整复刻原模型机构。

环境：Python + Pillow + NumPy；中文排版默认使用 Windows 微软雅黑 `C:/Windows/Fonts/msyh.ttc`。

```powershell
python build_assets.py
```

脚本仅重建本目录生成文件。源图集已随目录保存，不依赖临时提取目录。若在 Blockbench 手工修改模型，请另存新名字或新目录，避免下一次脚本重建覆盖手改。
